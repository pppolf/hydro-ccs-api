# 部署验收

## 检查安装

1. 用 Hydro 实际服务用户注册插件并重启服务，确认日志没有插件加载错误。
2. 系统设置出现“CCS 比赛数据接口”，设置独立 Basic 用户名/密码和测试比赛清单。
3. 使用固定时间 `acm` 测试比赛，确认主站域 `system` 和域内 URL/允许清单一致。
4. 读取 `/api/ccs`，确认 `provider.name` 为 `hydro-ccs-api`，版本与本次安装匹配。
5. 无凭据请求应为 401，未允许的比赛应为 403；允许清单为空时两类账号均不能读取比赛。

## 真实比赛与直播

1. 创建两个选手、一个打星队和一个比赛管理员账号，验证队伍、题目、语言和气球颜色。
2. 提交真实 WA、AC，并等待 Hydro journal 更新；比较原生榜与 CCS 榜的解题数、罚时和名次。
3. 检查同秒提交、相同解题数、相同秒级罚时以及团队成员代提交。
4. 封榜后提交并判 AC：Basic 看不到结果，未封榜读取密钥可见；提前封榜、解封、重新封榜均需验证历史回放。
5. 保存 event-feed token，断开后续传；重启 Hydro 后再续传，确认无重复消费或数据缺失。
6. 测试重判：出现新判题事件，旧持久事件不会被覆盖。
7. 修改密码、移除比赛，验证已有流在后续检查时结束；恢复连接使用新凭据。
8. 用实际版本 ICPC Live / CDS 连接，检查 `/scoreboard` 与软件显示的排名差异。

## 代理与运维

- HTTPS 反向代理保留鉴权头，关闭 event-feed 的响应缓冲，读取超时应超过心跳间隔。参考 [Nginx 示例](../examples/nginx.conf)。
- 只有独立设置和 `hydro.ccs.api.*` 日志属于本插件。不要用清理插件日志的方式修改原生比赛数据。
- 两个 Mongo 日志集合应一并备份；长期比赛需监测日志容量。
- 插件使用轮询快照生成事件；重新初始化和停机期间的历史限制见 [API 文档](API.md)。
- 若另有插件限制访客或特定账户的所有请求，应在测试环境检查中间件共存行为；不要通过关闭本插件鉴权处理冲突。

## 当前自动化验证边界

自动化检查包括真实 Hydro 5.1 设置注册器、真实宿主类型、隔离模型、持久事件逻辑和本地 HTTP 流；不依赖运行中的 MongoDB。上述实机/真实服务器步骤必须在部署环境执行，不能由单元测试结果替代。
